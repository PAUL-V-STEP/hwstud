# CLAUDE.md — сайт курса hwstud.ru

Инструкция для Claude Code. Прочитай этот файл целиком, затем `REQUIREMENTS.md`, затем файлы из `docs/` по порядку. При противоречии приоритет такой: этот файл → `REQUIREMENTS.md` → `docs/04-HOSTING-REGRU.md` → `docs/03-ARCHITECTURE.md` → `docs/01-FUNCTIONS.md` → `docs/02-DESIGN.md` → `docs/05-HOMEWORK-UPLOAD.md` → `docs/06-HELP.md`.

## Что строим

Сайт курса преподавателя (П. В. Степанов) для 4 групп студентов, до 20 человек в группе:

- лекции: слайды-картинки и текст к ним, исходные PDF и PPTX студентам не выдаются;
- общий глоссарий и литература курса;
- домашние задания с настраиваемым числом от 0 до 10, изменяемым порядком и загрузкой файлов;
- проверка работ агентом GPT через ProxyAPI, с одобрением преподавателем;
- объявления, переписка студента с преподавателем, уведомление на почту;
- админка: результаты, открытие лекций, режим экзамена, монитор баланса ProxyAPI;
- встроенные разделы «Помощь» и «Загрузка файлов»: студент видит только свою инструкцию, преподаватель — обе.

Вход студентов — только по нику, без пароля, ФИО и почты. Ник уникален на всём сайте. Вход преподавателя — по одному паролю.

## Главное правило: минимум инструментов

Разрешено только то, что перечислено в `03-ARCHITECTURE.md`, раздел 1. Всё остальное — запрещено без явного разрешения пользователя.

Запрещено:

- Docker, Kubernetes, Nginx (вместо него Caddy), Apache;
- Redis, Celery, RabbitMQ, любые брокеры и отдельные процессы-воркеры;
- PostgreSQL, MySQL, ORM (SQLAlchemy, Tortoise), Alembic;
- Node.js, npm, сборщики (Vite, Webpack), React, Vue, Svelte, Tailwind, TypeScript;
- CDN и любые внешние ресурсы на страницах: шрифты, скрипты, стили, счётчики, аналитика;
- внешние сервисы и любые исходящие запросы сервера, кроме ProxyAPI и SMTP почтового ящика преподавателя (в том числе проверка ссылок литературы);
- cron, таймеры systemd и отдельные скрипты для фоновых задач: всё расписание живёт в фоновом цикле приложения;
- SDK OpenAI: запросы к ProxyAPI — обычным `httpx`.

Если без инструмента задача не решается, остановись и спроси пользователя.

## Порядок работы

Делай по этапам. После каждого этапа — запуск локально, тесты `pytest`, короткий отчёт пользователю на русском языке. Следующий этап — после подтверждения.

1. **Каркас.** Структура проекта, база SQLite и миграции, вход только по нику (ограничения: 4 группы, 20 ников в группе, правила ника), вход преподавателя, общий шаблон страниц, темы «Тетрадь» и «Синька», процессная панель. Фоновый цикл с очередью `jobs`, потоками и семафорами. Почтовый модуль SMTP и кнопка «Отправить пробное письмо». Общий клиент ProxyAPI `proxyapi.py` с таблицей ответов (`03-ARCHITECTURE.md`, раздел 8.4), базовый `balance.py`: запрос баланса, пауза и снятие паузы. Скрипт `check_models` для обеих моделей (раздел 8.1) — отчёт пользователю до этапа 2. Проверочные запросы могут быть платными; прикладные запросы начинаются только после подтверждения моделей, картинок и JSON. Цены преподаватель отдельно сверяет с каталогом ProxyAPI.
2. **Лекции.** Загрузка пары PPTX + PDF (до 40 МБ каждый), блокирующие проверки и предупреждения, предпросмотр, «Сохранить на сайте», обновление по названию, удаление исходных файлов, просмотр «Слайд + текст» и «Конспект», ограничение скачивания, ручное открытие и скрытие лекций, режим студента для преподавателя. Задачи GPT `parse_abbr` и `abbr_guess`, ограничения распаковки, квота незавершённых импортов, срок предпросмотра, сохранение через папку версии с восстановлением после сбоя.
3. **Глоссарий и литература.** Разбор «Сокращения:» и источников из заметок, экраны подтверждения, общий глоссарий, подсветка сокращений, выгрузки.
4. **Задания и агент.** Формы 4 заданий, загрузка файлов с ограничениями объёма и семафором `upload_parse`, попытки, статусная модель, очередь проверки, запрет автоматического повторного платного запроса после перезапуска, одобрение преподавателем, таблица результатов, CSV. Полный монитор баланса ProxyAPI, резерв на проверку, письма о балансе.
5. **Связь.** Объявления, переписка, лимит 10 сообщений в сутки, письма о сообщениях и переход на сводку.
6. **Экзамен, кабинет и данные.** Режим экзамена, матрица Эйзенхауэра, личный SWOT, кривая распределения, страница «О курсе и авторе», страницы «Помощь» и «Загрузка файлов» со студенческой и преподавательской версиями и серверным разграничением доступа, резервные копии, архивы, проверка архива, удаление данных студентов с продолжением после сбоя, сценарий восстановления.
7. **Установка.** Файлы для сервера по `04-HOSTING-REGRU.md`: unit systemd, Caddyfile, инструкция `DEPLOY.md`.

На сервер ничего не устанавливай и не подключайся к нему, пока пользователь не попросит отдельно.

## Правила кода

- Python 3.12, FastAPI, шаблоны Jinja2, SQL — стандартный модуль `sqlite3`.
- Один процесс uvicorn с одним worker. Фоновые задачи — внутри этого процесса (`asyncio`), очередь — таблица в SQLite.
- Страницы собираются на сервере. JavaScript — небольшие собственные модули без библиотек, только там, где без него нельзя: анимация навигации, переключение темы без перезагрузки, просмотр слайдов, подсказки сокращений, загрузка файлов с прогрессом, перетаскивание плановой даты на диаграмме Ганта, кнопки «Скопировать», подтверждения и обновление статусов в админке, сохранение позиции прокрутки после отправки формы. Без JavaScript страницы читаются и формы отправляются.
- Все тексты интерфейса на русском, тон — `02-DESIGN.md`, раздел 9. Текст не мельче 14 px.
- Секреты только в `.env`: ключ ProxyAPI, пароль преподавателя (в виде хеша), пароль приложения SMTP, секрет сессий. `.env` не попадает в git, в репозитории — `.env.example` без значений.
- Время в базе — UTC, на экране — Europe/Moscow.
- Тесты — `pytest`, без внешних сетевых вызовов: ProxyAPI и SMTP подменяются заглушками.

## Что не делать без спроса

- Не публиковать сайт и не размещать материалы лекций в открытом доступе.
- Не оплачивать и не заказывать услуги.
- Не запрашивать и не вставлять ключи и пароли в код или в чат: пользователь вводит их в `.env` сам.
- Не менять функции и дизайн «по своему вкусу»: если в документах пробел, предложи вариант и спроси.

## Готово, когда

- Все функции из `REQUIREMENTS.md` и `01-FUNCTIONS.md` работают и проверены тестами или ручным сценарием, описанным в `TESTING.md`.
- Тестами покрыты: функция доступа `access.py` (скрытие, группы, экзамен, режим студента, файл работы), все переходы статусов работы, лимиты попыток и объёма, извлечение текста и до 5 изображений JPEG/PNG из DOCX в порядке документа, отказ на шестом изображении и на неподдерживаемом формате, ограничения распаковки, все ответы ProxyAPI из раздела 8.4, пауза и снятие паузы по балансу, восстановление задач `jobs` после перезапуска без повторного платного запроса, прерванное сохранение лекции и прерванное удаление данных, а также ролевой доступ к страницам «Помощь» и «Загрузка файлов»: студент получает только свою версию, преподаватель — обе, преподавательский текст отсутствует в HTML студента.
- Страница без слайдов при первом заходе передаёт не больше 300 КБ (сжатый объём вместе со шрифтами, иконками и логотипами, без картинок слайдов), на страницах нет внешних запросов.
- Приложение работает в пределах 2 ГБ памяти сервера (см. `04-HOSTING-REGRU.md`).
- Есть `README.md` (запуск локально), `DEPLOY.md` (установка на REG.RU и восстановление из копии), `TESTING.md` (результат `check_models` и ручные сценарии), `.env.example`.
