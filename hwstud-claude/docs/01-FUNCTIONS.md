# Функции сайта курса hwstud.ru

Финальная версия 2.1 от 23.11.2026. Описание функций для сборки сайта. Техническая реализация — в 03-ARCHITECTURE.md, ограничения сервера — в 04-HOSTING-REGRU.md.

Состав: один сервер VPS REG.RU, Python FastAPI, SQLite, Caddy (HTTPS), systemd. Внешних сервисов два: ProxyAPI (модели GPT) и SMTP-сервер почтового ящика преподавателя (уведомления). Других обращений сервера к внешним адресам нет.

## 0. Общие правила

- **Группы.** 4 группы, начальные названия «Группа 1» … «Группа 4», преподаватель переименовывает их в админке.
- **Выбор групп.** Везде, где выбираются группы (лекции, объявления, экзамен), пустой выбор означает «все группы». Чтобы никому не показывать, используется отдельный переключатель «Скрыта» или «Выключено», а не пустой список.
- **Шкала баллов.** Целые числа от 0 до 10 для каждого задания.
- **Время.** Все даты на экране — по Москве.

## 1. Студенты: вход и кабинет

- Вход без пароля, только по нику. При первом входе студент вводит ник и выбирает группу (одну из 4), дальше входит по нику. Браузер помнит вход 90 дней.
- У сайта нет полей для ФИО, почты и телефона студента. Студент может сам написать эти данные в работе или сообщении — тогда они хранятся вместе с работой или сообщением и удаляются с ними (раздел 12). Какой ник принадлежит какому студенту, преподаватель знает сам, вне сайта. На форме первого входа подсказка: «Не используйте в нике фамилию и имя полностью».
- **Правила ника:**
  - 3–24 символа: латинские буквы, цифры, `_` и `-`;
  - пробелы по краям отбрасываются;
  - регистр не различается: `Ivan_2` и `ivan_2` — один ник;
  - кириллица не допускается, чтобы не было похожих на вид ников из разных алфавитов (латинская «a» и русская «а»).
- **Ограничения:** в группе не больше 20 ников; ник уникален на всём сайте, иначе вход по одному нику был бы неоднозначным.
- В кабинете студент видит статус каждой текущей работы: «Не сдано», «На проверке», «На доработку», «Принята», «Попытки исчерпаны» (раздел 5.3).
- Кнопка «Запросить разбор» у проверенной работы: запрос попадает к преподавателю, разбор появляется в кабинете после его ответа.

## 2. Лекции

### 2.1. Загрузка (админка)

- Преподаватель загружает пару файлов: PPTX с заметками и PDF той же презентации, каждый до 40 МБ.
- Одновременно допускается не больше 5 активных импортов (`processing`, `waiting_gpt`, `paused_no_funds`, `ready`, `saving`) общим объёмом до 1 ГБ. При превышении квоты новая загрузка не начинается; преподаватель видит предложение сохранить, отменить или дождаться завершения прежних импортов.
- Картинки слайдов сайт берёт из PDF, текст к слайдам — из заметок PPTX, части лекции — из «Разделов» PowerPoint.
- **Новая лекция или обновление.** Сайт сравнивает название загружаемой лекции (заголовок первого слайда, его можно поправить на экране предпросмотра) с названиями уже сохранённых. При совпадении предлагается «Обновить лекцию «…»», иначе — «Новая лекция». Выбор подтверждает преподаватель. Названия сравниваются без учёта регистра, лишних пробелов и различия «е/ё».
- **Проверки, которые не дают сохранить лекцию:**
  - файл не открывается, больше 40 МБ или после распаковки слишком велик (больше 300 МБ, PDF больше 300 страниц);
  - число слайдов в PPTX и PDF не совпадает;
  - в PPTX нет ни одной заметки;
  - разбор сокращений через GPT (сложные строки и поиск сокращений без расшифровки, раздел 3) ещё идёт или стоит на паузе из-за баланса ProxyAPI (раздел 11). После пополнения разбор продолжается сам, кнопка «Сохранить на сайте» становится активной.
- **Проверки-предупреждения** (сохранить можно, предупреждения видны в предпросмотре):
  - слайды без заметок — список номеров;
  - заголовок слайда в PPTX не найден в тексте соответствующей страницы PDF — список номеров. Сравнение примерное: регистр, переносы строк, лишние пробелы, мягкие переносы и лигатуры не учитываются;
  - сокращения, которые не удалось разобрать.
- Перед сохранением есть предпросмотр, потом кнопка «Сохранить на сайте». Новая лекция сохраняется скрытой (раздел 2.3).
- **Срок предпросмотра.** Пока идёт разбор или он ждёт пополнения баланса, предпросмотр хранится без срока. Готовый предпросмотр хранится 7 дней, срок виден на экране. После срока сохранить его нельзя — лекцию нужно загрузить заново. Кнопка «Отменить» удаляет предпросмотр сразу.
- Сохранение не оставляет лекцию наполовину обновлённой: до конца сохранения студенты видят прежнюю версию, после — новую.
- Повторная загрузка обновляет лекцию по той же ссылке и не меняет её статус и выбор групп.
- После сохранения или отмены исходные файлы PPTX и PDF удаляются с сервера. На сайте остаются только картинки слайдов и текст. Для обновления лекции файлы загружаются заново.

### 2.2. Просмотр

- Режим «Слайд + текст»: слайд и текст к нему рядом.
- Режим «Конспект»: вся лекция одной лентой.
- Общее оглавление курса: лекции → части → слайды.
- Поиск по всем лекциям, доступным студенту.
- Ссылка на конкретный слайд.
- Навигация стрелками, клавишами и свайпом.
- **Ограничение скачивания:**
  - исходные файлы PPTX и PDF студентам не выдаются никогда и после импорта на сервере не хранятся;
  - слайды показываются картинками только после входа и проверки доступа;
  - кнопок «Скачать» и «Печать» нет, контекстное меню на слайде и печать страницы отключены.

  Это затрудняет массовое сохранение, но не исключает его: снимок экрана или инструменты разработчика браузера остаются возможны. Полной защиты сайт не обещает.

### 2.3. Открытие лекций для студентов

Преподаватель сам, вручную открывает и скрывает лекции. Автоматического открытия по дате нет.

- **Статусы лекции:**
  - «Скрыта» — студенты не видят лекцию ни в оглавлении, ни в поиске, прямая ссылка не открывается;
  - «Открыта» — лекция доступна студентам выбранных групп.
- Новая загруженная лекция по умолчанию скрыта.
- Открывать можно для всех групп или только для выбранных, если группы идут с разной скоростью: у каждой лекции переключатель «Скрыта / Открыта» и выбор групп.
- **Плановая дата** — справочное поле. По ней строится диаграмма Ганта курса, сама лекция по ней не открывается.
- **Отметка «Анонс»** (по умолчанию выключена): скрытая лекция показывается студентам только названием и плановой датой, без содержания. Включить анонс можно только при заполненной плановой дате.
- Названия лекций на сайте уникальны: две лекции с одинаковым названием (без учёта регистра, пробелов и «е/ё») сохранить нельзя.
- Преподаватель видит все лекции, включая скрытые, с пометкой «скрыта». Скрытую лекцию может просмотреть только преподаватель — в «режиме студента», то есть так, как её увидят студенты.
- Если лекцию снова скрыть, её глоссарий, сокращения и литература пропадают у студентов. Записи, общие с открытыми лекциями, остаются видны со ссылками только на открытые лекции.
- Режим экзамена (раздел 8) действует поверх этих настроек.
- Каждое открытие и скрытие записывается в журнал: кто, когда, какая лекция и для каких групп.

## 3. Глоссарий курса

- Общий для всех лекций, хранится на сайте.
- Пополняется из загружаемых лекций:
  - из блока «Сокращения:» в заметках (раздел 3.1);
  - из сокращений, найденных в тексте без расшифровки: сайт сам находит кандидатов (слова из заглавных букв, которых нет в глоссарии), GPT через ProxyAPI предлагает расшифровку по контексту с пометкой «черновик — проверить». Пока этот разбор не закончен, лекцию сохранить нельзя (раздел 2.1).
- Экран подтверждения при загрузке: «новые», «уже есть», «конфликты».
- Ручное редактирование в админке, отметка «проверено», скрытие термина.
- Номера слайдов у каждого термина обновляются автоматически. Если термин больше нигде не встречается, он помечается «не используется».
- **У студента:**
  - сокращения в тексте подсвечены, при наведении или касании видна расшифровка;
  - панель «Глоссарий» с поиском и переходом на слайды.
- **Выгрузка:** Excel (XLSX), Markdown, DOCX, PDF.
- **Блок для заметок PowerPoint:** текст для копирования в заметки слайда, кнопка «Скопировать» и файл TXT. Формат — одна строка: `Сокращения: BPMN — Business Process Model and Notation, нотация моделирования бизнес-процессов; KPI — Key Performance Indicator, ключевой показатель эффективности`. Сайт файлы PPTX не редактирует.

### 3.1. Сокращения из заметок: один раздел на лекцию и курс

В заметках PPTX у каждого слайда может быть свой блок «Сокращения: …», и одни и те же термины повторяются на многих слайдах. На сайте эти блоки не показываются у слайдов, а собираются в один раздел.

- Сайт находит в заметках строки, начинающиеся с «Сокращения:», и разбирает их на пары «термин — расшифровка».
- Сложные записи, где внутри расшифровки есть «;» (например, MoSCoW: Must; Should; Could; Won't или Q1, Q2), разбираются через GPT по ProxyAPI и попадают на экран подтверждения.
- Одинаковые термины со всех слайдов объединяются в одну запись. Если расшифровки различаются, запись получает пометку «конфликт», и преподаватель выбирает вариант.
- Итог добавляется в общий глоссарий курса. Термины, которые уже есть в глоссарии, не дублируются: к ним только добавляются номера слайдов.
- Блок «Сокращения: …» убирается из текста слайда, который видит студент. Вместо него сокращения подсвечиваются в тексте и раскрываются при наведении.
- У каждой лекции есть вкладка «Сокращения лекции»: выборка из общего глоссария, только термины этой лекции, со ссылками на слайды.
- Служебные строки, которые одинаково повторяются на многих слайдах (например, «Данные сквозного примера условные»), показываются один раз, в шапке лекции. Порог повтора задаёт преподаватель, по умолчанию — больше чем на половине слайдов.
- Исходный файл PPTX не меняется: разбор идёт только при загрузке на сайт.

## 4. Литература и материалы для изучения

Общий раздел курса со всеми источниками из всех лекций. Пополняется автоматически с каждой загруженной лекцией.

### 4.1. Откуда сайт берёт источники

- Слайд «Источники» или «Литература»: список в заметках последнего слайда.
- Ссылки в заметках к отдельным слайдам, вида «[1] Автор. Название. https://…».
- Номера [1], [5] в тексте: по ним сайт запоминает, на каких слайдах цитируется источник.

### 4.2. Карточка источника

- Автор, название, ссылка.
- Где используется: «Лекция 2, слайды 35, 70», со ссылкой на слайд.
- Тип: статья, документация, книга, руководство. Тип предлагает GPT, преподаватель подтверждает.
- Аннотация в 1–2 предложения. Готовит GPT по автору, названию и контексту лекции, преподаватель правит. Сайт сам внешние ссылки не открывает.
- Пометка «основное» или «дополнительное». Ставит преподаватель.

### 4.3. Просмотр и выгрузка

- Вид по лекциям, по темам или одним списком.
- Фильтр «основное / дополнительное» и поиск.
- В тексте лекции номера [n] кликабельны, всплывает описание источника и ссылка.
- Выгрузка всего раздела в PDF, DOCX или Markdown.

### 4.4. Обслуживание

- Дубли: одна статья из нескольких лекций распознаётся по адресу или по автору и названию и показывается один раз с пометкой «Лекции 1, 2».
- Экран подтверждения при загрузке: новые, уже известные, спорные.
- Сайт не проверяет, открываются ли ссылки: сервер не обращается к внешним адресам, кроме ProxyAPI и SMTP.
- Сайт хранит только ссылки и описания, копии статей не сохраняет.

## 5. Домашние работы

### 5.1. Задания (админка)

- Число заданий настраивается от 0 до 10. Их можно переставлять; номер и последовательность меняются без смены стабильного ID и потери работ. При уменьшении числа задания скрываются без удаления. У каждого активного задания в админке форма: название, условие (текст с простым форматированием), срок сдачи (дата и время), эталонное решение, критерии оценки, типичные ошибки, порог уверенности (по умолчанию 0,7).
- Эталон, критерии и типичные ошибки студенту не показываются.
- Изменения задания действуют для следующих проверок. Уже выставленные оценки не пересчитываются.
- После срока загрузка не закрывается, но работа получает пометку «после срока», видную преподавателю.

### 5.2. Загрузка работы

- Одна работа — один файл: PDF, JPG, PNG, TXT или DOCX, до 10 МБ.
- **Ограничения объёма**, чтобы одна проверка не стала дорогой:
  - текст (PDF с текстом, DOCX, TXT) — не больше 30 000 знаков;
  - PDF-скан — не больше 5 страниц;
  - смешанный PDF (часть страниц текстом, часть сканом) проверяется постранично: текст — не больше 30 000 знаков, страниц-сканов — не больше 5, всего — не больше 50 страниц;
  - фото — одно изображение в файле;
  - DOCX — не больше 5 растровых изображений JPEG/PNG в основном тексте документа: они передаются на проверку вместе с текстом в порядке их следования;
  - DOCX после распаковки — не больше 50 МБ.
- Работа сверх ограничений отклоняется сразу при загрузке, с понятным сообщением, и попытка не расходуется. Пример: «В скане 8 страниц, допускается 5. Уберите лишние страницы или загрузите текст в DOCX».
- Повторная загрузка открывается только после статуса «На доработку». Всего не больше 4 попыток на задание.
- Загруженный файл открывают только его владелец (студент, который его загрузил) и преподаватель. Другие студенты и посетители без входа доступа не имеют.
- Если сервер разбирает сразу несколько работ, следующая загрузка ждёт до 30 секунд. Дольше — сообщение «Сервер занят, повторите через минуту», попытка не расходуется.

### 5.3. Статусы работы

| Статус (внутренний) | Что видит студент | Что происходит |
|---|---|---|
| Не сдано | «Не сдано» | Можно загрузить файл |
| В очереди | «На проверке» | Ждёт отправки в GPT, в том числе при паузе из-за баланса |
| Проверяется ИИ | «На проверке» | Запрос к GPT отправлен |
| Ждёт одобрения | «На проверке» | ИИ выставил вердикт, баллы и комментарий; преподаватель ещё не решил |
| Требует проверки | «На проверке» | Уверенность ИИ ниже порога или ответ ИИ не получен; решение только за преподавателем |
| На доработку | «На доработку» + баллы и комментарий | Преподаватель решил; открыта следующая попытка, если они остались |
| Принята | «Принята» + баллы и комментарий | Итог |
| Попытки исчерпаны | «Попытки исчерпаны» + баллы и комментарий | Четвёртая попытка получила «На доработку». Дальше ничего не происходит |

- Пока решения преподавателя нет, студент не видит ни вердикт, ни баллы, ни комментарий.
- Преподаватель на экране работы видит предложение ИИ, может его принять как есть или исправить вердикт, баллы и комментарий, затем нажимает «Одобрить».
- Хранится только последний вердикт: баллы, вердикт и комментарий. Если преподаватель исправил предложение ИИ, исправленные значения заменяют его. История изменений не ведётся.
- В таблице результатов идёт последняя попытка по каждому заданию.

## 6. Агент проверки

- Фоновая очередь внутри приложения отправляет в GPT через ProxyAPI условие, эталон, критерии, типичные ошибки и работу.
- **Модели** (раздел 6.1 архитектуры): проверка работ — `openai/gpt-6.1-terra`, служебные задачи (разбор сокращений, тип и аннотация источника) — `openai/gpt-6-luna`. Обе поддерживают изображения и ответ в JSON по каталогу ProxyAPI. Модели меняются в `.env`.
- Ответ приходит в JSON: вердикт, баллы 0–10, список ошибок, классификация, уверенность, комментарий для студента.
- При уверенности ниже порога задания работа получает статус «Требует проверки».
- Перед отправкой работы в GPT сайт проверяет баланс ProxyAPI (раздел 11). Если средств нет, работа ждёт в очереди и уходит на проверку автоматически после пополнения.
- **Настройки:**
  - в `.env` — ключ и модели;
  - в разделе «Настройки» админки — общие параметры, пороги баланса, цены моделей для оценки расхода;
  - в форме задания — критерии, эталон, типичные ошибки, порог.

## 7. Админка преподавателя

- Вход по одному паролю.
- Таблица результатов «группа — ник — работа — статус — баллы», правка вердикта и выгрузка в CSV.
- Экран работы: файл студента (кроме преподавателя его видит только сам автор), предложение ИИ, поля решения, кнопка «Одобрить», кнопка «Проверить ИИ снова» (если ответ ИИ потерян при сбое).
- Очередь «Ждут одобрения» и «Требуют проверки», очередь запросов на разбор.
- Формы 4 заданий (раздел 5.1).
- Группы: названия, закрытие набора, блокировка ников.
- Журнал загрузок и действий.
- Список лекций с переключателем «Скрыта / Открыта», выбором групп, плановой датой и отметкой «Анонс» (раздел 2.3).
- Разделы «Лекции», «Глоссарий», «Литература» с экранами подтверждения.
- Разделы «Объявления» и «Сообщения» (разделы 9 и 10).
- «Настройки»: монитор баланса ProxyAPI (раздел 11), почта, пороги, служебные параметры.
- «Данные курса»: скачать копию базы и лекций, скачать архив работ, удалить данные студентов (раздел 12).

## 8. Режим экзамена

- Один набор настроек экзамена на сайт: переключатель «Включён», выбор групп, время начала и окончания (или «сразу» и «до выключения»). Пересечения нескольких экзаменов поэтому невозможны.
- **Закрывается всё учебное содержимое:** лекции, глоссарий, литература и поиск.
- На странице закрытого раздела выводится сообщение «Доступ к учебным материалам закрыт на время экзамена» и локальная иллюстрация `content-closed` (правила и размеры — `02-DESIGN.md`, разделы 2.5.1 и 5.10). Иллюстрация обозначает ограничение доступа, а не работу ИИ. Текст не обещает закрытие всего сайта: задания, объявления, переписка и помощь остаются доступны.
- Остаются доступны: объявления, переписка с преподавателем, раздел «Задания» — условия, загрузка работ и статусы, а также страницы «Помощь» и «Загрузка файлов» в соответствии с ролью.
- Режим экзамена действует поверх ручного открытия лекций: после окончания экзамена открытые лекции снова видны.

## 9. Объявления

- Преподаватель пишет объявление в админке: заголовок и текст. Необязательных ссылок на лекцию или задание в форме нет; параметры `link_type`, `lecture_id` и `assignment_id` обработчиком не принимаются.
- Адресат: все группы или выбранные.
- Публикация сразу или по дате и времени; дата снятия по желанию.
- Вид объявления: «обычное», «важное», «о сроке». Важное всегда закреплено. Обычное и о сроке можно закрепить отметкой «закреплено». Закреплённые стоят первыми.
- Новое объявление не содержит ссылки на учебный материал. Возврат из редактора ведёт в обзор админки; позиция на форме после отправки сохраняется по общим правилам `02-DESIGN.md`.
- У студента: лента на главной странице и в разделе «Объявления», непрочитанные выделены, на кнопке меню — счётчик новых.
- Сайт отмечает, кто из студентов открыл объявление. Преподаватель видит число прочитавших по группам.

## 10. Связь с преподавателем

- У каждого ника своя ветка переписки с преподавателем. Другие студенты её не видят.
- Студент пишет сообщение в окне «Вопрос преподавателю»: только текст, до 2000 знаков. Можно указать, к чему вопрос: лекция и слайд или задание.
- Ограничение от перегрузки: не больше 10 сообщений от одного ника за календарные сутки по Москве.
- **Уведомления на почту:**
  - о каждом новом сообщении сайт отправляет письмо на почту преподавателя: группа, ник, тема, текст и ссылка на ветку;
  - если за сутки уже ушло 30 писем о сообщениях, сайт до конца суток переходит на одно сводное письмо раз в час;
  - сводку раз в час можно включить и постоянно.
- Отвечает преподаватель только на сайте, в админке. Ответ сразу появляется в ветке студента, а на кнопке меню — отметка «новый ответ».
- Студент не указывает почту, поэтому об ответе он узнаёт на сайте.
- Статусы сообщения у студента: «отправлено», «прочитано преподавателем», «есть ответ».
- В админке: список веток по никам, непрочитанные сверху, поиск, закрытие ветки «вопрос решён».
- У ника одна ветка. Закрытая ветка у студента видна с пометкой «вопрос решён»; новое сообщение студента снова открывает эту же ветку.
- Отправка писем идёт через почтовый ящик преподавателя по протоколу SMTP. Отдельный сервис рассылок не нужен. Пароль приложения для ящика записывается в файл `.env` на сервере при установке, через веб-интерфейс он не вводится и не меняется.
- Чтобы письма не попадали в спам, преподаватель один раз добавляет адрес отправителя в контакты или в белый список своего почтового ящика.

## 11. Баланс ProxyAPI: проверка и монитор

Все функции с GPT — проверка работ, разбор сложных сокращений, тип и аннотации источников — оплачиваются с баланса ProxyAPI. Сайт следит за балансом сам и заранее предупреждает преподавателя.

### 11.1. Как сайт узнаёт баланс

- ProxyAPI отдаёт текущий баланс по запросу `GET https://api.proxyapi.ru/proxyapi/balance` с ключом сайта ([ProxyAPI, баланс](https://www.proxyapi.ru/docs/balance)).
- По умолчанию ключу этот запрос недоступен. В личном кабинете ProxyAPI, в разделе «Ключи API», у ключа сайта нужно включить разрешение «Запрос баланса».
- Если у ключа задан бюджет, ProxyAPI возвращает остаток бюджета ключа. Монитор показывает и остаток, и лимит бюджета.
- Сайт запрашивает баланс каждые 30 минут, после каждых 10 запросов к GPT и по кнопке «Проверить сейчас».
- Если средств не хватает, ProxyAPI отклоняет запрос с кодом 402 и ничего не списывает ([ProxyAPI, стоимость запроса](https://proxyapi.ru/docs/cost-of-request)). Сайт распознаёт этот ответ, даже если запрос баланса для ключа не включён.

### 11.2. Пороги и пауза

| Уровень | Условие | Что делает сайт |
|---|---|---|
| Норма | Баланс выше порога «Мало» | Всё работает |
| Мало | Ниже порога «Мало» (по умолчанию 300 ₽) | Жёлтая плашка в админке, письмо преподавателю |
| Критично | Ниже порога «Критично» (по умолчанию 100 ₽) | Красная плашка, письмо. Запросы к GPT ещё отправляются |
| Нет средств | ProxyAPI ответил 402 или баланс ниже резерва на проверку | Пауза: запросы к GPT не отправляются, работы ждут в очереди, письмо |
| Неизвестно | Запрос баланса не разрешён или ответа нет больше 2 часов | Серая плашка «баланс неизвестен». Пороги «мало» и «критично» не считаются, писем об уровнях нет. Работы проверяются, пока ProxyAPI не ответит 402 |

- **Резерв на проверку** — одно правило для всего сайта. Это оценка самой дорогой проверки (наибольший объём из раздела 5.2, пять изображений — страниц-сканов PDF или картинок DOCX, наибольшая длина ответа, цены модели из настроек) с запасом 1,5. При ценах на 22.11.2026 и `image_tokens = 1500` это около 14,24 ₽, на экране — 15 ₽. Это оценка, а не гарантия: точное число токенов до запроса неизвестно. Жёстко ограничить расход можно только бюджетом ключа в кабинете ProxyAPI.
- **Ключ отклонён** (ответ GPT 401 или 403): все запросы к GPT останавливаются, работы ждут в очереди, преподаватель получает письмо. После исправления ключа — кнопка «Проверить ключ». Ответ 403 только на запрос баланса означает лишь отсутствие разрешения на чтение баланса и не останавливает GPT: уровень становится «Неизвестно».
- Письмо о каждом уровне отправляется один раз при переходе на этот уровень и повторяется не чаще раза в 12 часов, пока уровень держится.
- **Снятие паузы:**
  - если запрос баланса разрешён, баланс проверяется каждые 5 минут; как только он выше резерва на проверку, пауза снимается;
  - если запрос баланса не разрешён, каждые 15 минут сайт отправляет первую задачу из очереди как пробную. Ответ 402 означает, что пауза продолжается, и ничего не списывается. Успешный ответ снимает паузу;
  - кнопка «Возобновить сейчас» в мониторе делает такую же пробную отправку сразу.
- После снятия паузы работы уходят по порядку, преподаватель получает письмо «Баланс восстановлен, в очереди N работ».

### 11.3. Монитор в разделе «Настройки → ProxyAPI»

- Текущий баланс, время последней проверки, уровень.
- Бюджет ключа: лимит и израсходовано, если бюджет задан.
- **Расход за сегодня, за 7 дней, за месяц.** Это оценка по токенам из ответов ProxyAPI и ценам моделей, которые преподаватель указывает в настройках. Начальные цены — из каталога ProxyAPI на 22.11.2026: `gpt-6.1-terra` — 260 ₽ ввод и 1300 ₽ вывод за 1 млн токенов, `gpt-6-luna` — 30 ₽ и 150 ₽ ([ProxyAPI, модели OpenAI](https://www.proxyapi.ru/models/openai)). Точный расход виден в кабинете ProxyAPI.
- Средняя оценочная стоимость одной проверки работы — по последним 20 проверкам, по их собственным токенам. Служебные задачи считаются отдельно.
- Прогноз: «хватит примерно на N проверок» и «примерно до такой-то даты» при темпе расхода последних 7 дней.
- Очередь: сколько задач ждёт, сколько из них из-за нехватки средств.
- Последние ошибки ProxyAPI: 401 (неверный ключ), 402 (нет средств), 429 (слишком много запросов) — с датой и пояснением.
- Состояние ключа: «запрос баланса разрешён / не разрешён», с подсказкой, где его включить.
- Кнопки «Проверить сейчас», «Отправить пробный запрос», «Возобновить сейчас», «Пополнить баланс». Последняя открывает раздел пополнения личного кабинета ProxyAPI в новой вкладке. Адрес кнопки преподаватель вставляет в поле «Ссылка на пополнение» в этом же разделе; пока поле пустое, кнопка ведёт на главную страницу ProxyAPI. Сайт платежей не делает.
- График баланса за 30 дней.

### 11.4. Где ещё видно

- На главной странице админки — плашка уровня «мало», «критично» или «нет средств» с прогнозом и кнопкой «Открыть монитор». При устаревших или недоступных данных баланса выводится серая плашка «баланс неизвестен», при 401/403 — красная плашка «Проверьте ключ ProxyAPI» и кнопка «Проверить ключ» после исправления `.env` и перезапуска.
- В очереди у задач, ждущих пополнения, — пометка «ждёт пополнения ProxyAPI».
- Студентам баланс не показывается.

### 11.5. Экономия средств

- В каждом запросе к GPT задаётся ограничение длины ответа: 1500 токенов для проверки работ, 2000 для служебных задач. Без него ProxyAPI при проверке достаточности средств закладывает максимально возможный ответ модели ([ProxyAPI, стоимость запроса](https://proxyapi.ru/docs/cost-of-request)).
- Рекомендуется задать бюджет ключа сайта в кабинете ProxyAPI, например на месяц курса.
- Автопополнение в ProxyAPI сайт не включает и не настраивает.
- **Оценка на курс** при ценах на 22.11.2026: обычная проверка — 2–4 ₽. При максимуме 80 студентов × 10 заданий × в среднем 1,5 попытки — около 1200 проверок, примерно 3800 ₽. Худший случай — 3200 проверок наибольшего объёма с пятью изображениями (сканами PDF или картинками DOCX), около 9,49 ₽ каждая при `image_tokens = 1500`, — примерно 30 370 ₽. При меньшем текущем числе заданий оценка пропорционально снижается. После `check_models` оценка пересчитывается с фактическим `image_tokens`.

## 12. Данные курса и резервные копии

- Ежедневная копия базы и еженедельный архив «база + лекции» делаются автоматически ночью (04-HOSTING-REGRU.md, раздел 6).
- Кнопка «Скачать копию сайта» — последний архив «база + лекции».
- Кнопка «Скачать архив работ» — архив всех загруженных работ, собирается по запросу. Одновременно хранится не более одного такого архива; задача `delete_temp` удаляет его с сервера через час после создания, даже если его не скачали.
- Каждое воскресенье сайт сам проверяет свежий архив: распаковывает его и проверяет целостность базы. Результат виден в «Данных курса», ошибка приходит письмом.
- Восстановление из копии описано в DEPLOY.md и проверяется один раз до начала курса.
- **Кнопка «Удалить данные студентов»** — после окончания курса, с двойным подтверждением:
  - удаляются ники, работы, переписка, отметки о прочтении и просмотрах, временные архивы работ;
  - в журнале действий ники заменяются на «удалённый студент»;
  - сначала делается новая копия уже без данных студентов, и только потом удаляются все прежние копии, в которых эти данные остались. Так у сайта всё время есть хотя бы одна копия;
  - если сервер перезапустится посреди удаления, оно продолжится с того же шага.

  Лекции, глоссарий, литература, задания и настройки остаются.

## 14. Помощь и инструкции

- После входа доступен раздел **«Помощь»** с двумя страницами: «Работа с сайтом» и «Загрузка файлов».
- Страница «Работа с сайтом» описывает возможности сайта и правила работы с ним. Страница «Загрузка файлов» содержит пошаговые инструкции и ограничения файлов.
- Существуют два варианта каждой инструкции: для студента и для преподавателя.
- Студент видит только студенческий вариант: правила работы с сайтом и загрузку домашних заданий. Преподавательские тексты не включаются в его HTML и недоступны по прямой ссылке.
- Преподаватель видит оба варианта с переключателем «Студенту / Преподавателю»: полную студенческую инструкцию, правила администрирования и загрузку лекций PPTX + PDF.
- Из карточки задания есть ссылка «Как загрузить работу», из формы импорта лекции — «Инструкция по загрузке лекции». Открывается соответствующий ролевой вариант.
- Обе страницы остаются доступны во время экзамена, работают без JavaScript и не используют внешние ресурсы.
- Полное содержание страниц и правила доступа — `docs/06-HELP.md`; студенческая инструкция по загрузке — `docs/05-HOMEWORK-UPLOAD.md`.
