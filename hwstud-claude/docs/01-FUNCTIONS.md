# Функции сайта курса hwstud.ru

Версия 1.6 от 22.11.2026. Описание функций для сборки сайта. Техническая реализация — в 03-ARCHITECTURE.md, ограничения сервера — в 04-HOSTING-REGRU.md.

Состав: один сервер VPS REG.RU, Python FastAPI, SQLite, Caddy (HTTPS), systemd. Единственный внешний сервис — ProxyAPI (модели GPT).

## 1. Студенты: вход и кабинет

- Вход без пароля, только по нику. При первом входе студент вводит ник и выбирает группу (одну из 4), дальше входит по нику. Браузер помнит вход 90 дней.
- Сайт не спрашивает и не хранит ФИО, почту и телефон студента. Какой ник принадлежит какому студенту, преподаватель знает сам, вне сайта.
- Ограничения: в группе не больше 20 ников; ник уникален на всём сайте, иначе вход по одному нику был бы неоднозначным.
- В кабинете студент видит статус каждой из 4 работ: «Не сдано», «На проверке», «Принята», «На доработку», «Требует проверки».
- Кнопка «Запросить разбор»: запрос попадает к преподавателю, а разбор появляется в кабинете после его одобрения.

## 2. Лекции

### 2.1. Загрузка (админка)

- Преподаватель загружает пару файлов: PPTX с заметками и PDF той же презентации.
- Картинки слайдов сайт берёт из PDF, текст к слайдам — из заметок PPTX.
- Части лекции берутся из «Разделов» PowerPoint.
- Проверки при загрузке:
  - число слайдов в PPTX и PDF совпадает;
  - показывается список слайдов без заметок;
  - заголовки слайдов в PPTX совпадают с текстом на страницах PDF.
- Перед сохранением есть предпросмотр, потом кнопка «Сохранить на сайте». Сохранённая лекция остаётся скрытой от студентов, пока её не откроют (раздел 2.3).
- Повторная загрузка обновляет лекцию по той же ссылке и не меняет её статус «Скрыта / Открыта».

### 2.2. Просмотр

- Режим «Слайд + текст»: слайд и текст к нему рядом.
- Режим «Конспект»: вся лекция одной лентой.
- Общее оглавление курса: лекции → части → слайды.
- Поиск по всем лекциям.
- Ссылка на конкретный слайд.
- Навигация стрелками, клавишами и свайпом.
- Защита от скачивания: показываются картинки, а не файл PDF, правый клик и печать отключены.

### 2.3. Открытие лекций для студентов (новое)

Преподаватель сам решает, какие лекции видят студенты. Переключатель есть у каждой лекции отдельно.

- Статусы лекции:
  - «Скрыта» — студенты не видят лекцию ни в оглавлении, ни в поиске, а прямая ссылка на неё не открывается;
  - «Открыта» — лекция доступна студентам.
- Новая загруженная лекция по умолчанию скрыта. Студенты увидят её только после того, как преподаватель включит переключатель или задаст дату открытия.
- Открывать можно сразу или по дате и времени, например «открыть 05.12.2026 в 10:00». Так материал открывается последовательно, по ходу курса.
- Открывать можно для всех групп или только для выбранных, если группы идут с разной скоростью.
- Отметка «Анонс» (по умолчанию выключена): скрытая лекция с заданной датой открытия показывается студентам только названием и датой, без содержания.
- Преподаватель видит все лекции, включая скрытые, с пометкой «скрыта». Скрытую лекцию до открытия может просмотреть только преподаватель — в «режиме студента», то есть так, как её увидят студенты.
- Если лекцию снова скрыть, её глоссарий, сокращения и литература тоже пропадают у студентов. Записи, общие с открытыми лекциями, остаются видны со ссылками только на открытые лекции.
- Режим экзамена (раздел 8) действует поверх этих настроек: он может временно закрыть и открытые лекции.
- Каждое открытие и закрытие записывается в журнал: кто, когда, какая лекция и для каких групп.

## 3. Глоссарий курса

- Общий для всех лекций, хранится на сайте.
- Пополняется из загружаемых лекций:
  - из блока глоссария в заметках;
  - автоматически — из сокращений, найденных в тексте без расшифровки: GPT через ProxyAPI предлагает расшифровку по контексту с пометкой «черновик — проверить».
- Экран подтверждения при загрузке: «новые», «уже есть», «конфликты».
- Ручное редактирование в админке, отметка «проверено», скрытие термина.
- Номера слайдов у каждого термина обновляются автоматически. Если термин больше нигде не встречается, он помечается «не используется».
- У студента:
  - сокращения в тексте подсвечены, при наведении или касании видна расшифровка;
  - панель «Глоссарий» с поиском и переходом на слайды.
- Выгрузка в Excel или Markdown и блок для заметок PowerPoint.

### 3.1. Сокращения из заметок: один раздел на лекцию и курс (новое)

В заметках PPTX у каждого слайда может быть свой блок «Сокращения: …», и одни и те же термины повторяются на многих слайдах. На сайте эти блоки не показываются у слайдов, а собираются в один раздел.

- Сайт находит в заметках строки, начинающиеся с «Сокращения:», и разбирает их на пары «термин — расшифровка».
- Сложные записи, где внутри расшифровки есть «;» (например, MoSCoW: Must; Should; Could; Won't или Q1, Q2), разбираются через GPT по ProxyAPI и попадают на экран подтверждения.
- Одинаковые термины со всех слайдов объединяются в одну запись. Если расшифровки на разных слайдах различаются, запись получает пометку «конфликт», и преподаватель выбирает вариант.
- Итог добавляется в общий глоссарий курса (раздел 3). Термины, которые уже есть в глоссарии, не дублируются: к ним только добавляются номера слайдов.
- Блок «Сокращения: …» убирается из текста слайда, который видит студент. Вместо него сокращения подсвечиваются в тексте и раскрываются при наведении.
- У каждой лекции есть вкладка «Сокращения лекции»: выборка из общего глоссария, только термины этой лекции, со ссылками на слайды.
- Служебные строки, которые одинаково повторяются на многих слайдах (например, «Данные сквозного примера условные»), показываются один раз, в шапке лекции. Порог повтора задаёт преподаватель, по умолчанию — больше чем на половине слайдов.
- Исходный файл PPTX не меняется: разбор идёт только при загрузке на сайт.

## 4. Литература и материалы для изучения (новое)

Общий раздел курса со всеми источниками из всех лекций. Пополняется автоматически с каждой загруженной лекцией.

### 4.1. Откуда сайт берёт источники

- Слайд «Источники» или «Литература»: список в заметках последнего слайда.
- Ссылки в заметках к отдельным слайдам, вида «[1] Автор. Название. https://…».
- Номера [1], [5] в тексте: по ним сайт запоминает, на каких слайдах цитируется источник.

### 4.2. Карточка источника

- Автор, название, рабочая ссылка.
- Где используется: «Лекция 2, слайды 35, 70», со ссылкой на слайд.
- Тип: статья, документация, книга, руководство. Тип предлагает GPT, преподаватель подтверждает.
- Аннотация в 1–2 предложения. Готовит GPT, преподаватель правит.
- Пометка «основное» или «дополнительное». Ставит преподаватель.

### 4.3. Просмотр и выгрузка

- Вид по лекциям, по темам или одним списком.
- Фильтр «основное / дополнительное» и поиск.
- В тексте лекции номера [n] кликабельны, всплывает описание источника и ссылка.
- Выгрузка всего раздела в PDF, DOCX или Markdown, чтобы раздать студентам или положить в учебно-методический комплекс.

### 4.4. Обслуживание

- Дубли: одна статья из нескольких лекций распознаётся по адресу или по автору и названию и показывается один раз с пометкой «Лекции 1, 2».
- Экран подтверждения при загрузке: новые, уже известные, спорные.
- Проверка ссылок раз в неделю: в админке видно, какие адреса перестали открываться.
- Раздел подчиняется режиму экзамена: его можно скрыть вместе с материалами или оставить открытым.
- Сайт хранит только ссылки и описания, копии статей не сохраняет, чтобы не было вопросов с авторскими правами.

## 5. Домашние работы

- 4 задания.
- Файлы PDF, JPG, PNG, TXT, DOCX до 10 МБ.
- Повторная загрузка открывается только после статуса «На доработку», не больше 4 попыток на задание.

## 6. Агент проверки

- Фоновая очередь внутри приложения отправляет в GPT через ProxyAPI условие, эталон, критерии и работу.
- Ответ приходит в JSON: вердикт, баллы, список ошибок, классификация, уверенность.
- При уверенности ниже 0,7 работа получает статус «Требует проверки».
- Настройки:
  - в файле .env — ключ и модель;
  - в таблице настроек — общие параметры;
  - в таблице заданий — критерии, эталон, типичные ошибки, порог.
- Комментарии агента студенту не видны до одобрения преподавателем.
- Перед отправкой работы в GPT сайт проверяет баланс ProxyAPI (раздел 11). Если средств нет, работа остаётся в очереди и уходит на проверку автоматически после пополнения. Студент видит статус «На проверке», работа не теряется.

## 7. Админка преподавателя

- Вход по одному паролю.
- Таблица результатов «группа — студент — работа — статус», правка вердикта и выгрузка в CSV.
- Очередь запросов на разбор.
- Блокировка ников и закрытие набора.
- Журнал загрузок.
- Список лекций с переключателем «Скрыта / Открыта», датой открытия и выбором групп (раздел 2.3).
- Разделы «Лекции», «Глоссарий», «Литература» с экранами подтверждения.
- Разделы «Объявления» и «Сообщения» (разделы 9 и 10).
- Монитор баланса ProxyAPI в разделе «Настройки» и плашка на главной админки при нехватке средств (раздел 11).

## 8. Режим экзамена

- Переключатель закрывает материалы для всех или для выбранных групп, сразу или по расписанию.
- Отдельно настраивается, закрывать ли глоссарий и литературу.
- Объявления и переписка с преподавателем в режиме экзамена остаются доступны.

## 9. Объявления (новое)

- Преподаватель пишет объявление в админке: заголовок, текст, при необходимости ссылка на лекцию или задание.
- Адресат: все группы или выбранные.
- Публикация сразу или по дате и времени; дата снятия по желанию.
- Отметка «закреплено»: такие объявления стоят первыми.
- У студента: лента на главной странице и в разделе «Объявления», непрочитанные выделены, на кнопке меню — счётчик новых.
- Сайт отмечает, кто из студентов открыл объявление. Преподаватель видит число прочитавших по группам.

## 10. Связь с преподавателем (новое)

- У каждого ника своя ветка переписки с преподавателем. Другие студенты её не видят.
- Студент пишет сообщение в окне «Вопрос преподавателю»: только текст, до 2000 знаков. Можно указать, к чему вопрос: лекция и слайд или задание.
- Ограничение от перегрузки: не больше 10 сообщений от одного ника в сутки.
- О каждом новом сообщении сайт отправляет письмо на почту преподавателя: группа, ник, тема, текст и ссылка на ветку. Если сообщений много, можно включить одно сводное письмо раз в час.
- Отвечает преподаватель только на сайте, в админке. Ответ сразу появляется в ветке студента, а на кнопке меню — отметка «новый ответ».
- Студент не указывает почту (вход только по нику), поэтому об ответе он узнаёт на сайте.
- Статусы сообщения у студента: «отправлено», «прочитано преподавателем», «есть ответ».
- В админке: список веток по никам, непрочитанные сверху, поиск, закрытие ветки «вопрос решён».
- Отправка писем идёт через почтовый ящик преподавателя по протоколу SMTP. Отдельный сервис рассылок не нужен. Пароль приложения для ящика вводится в настройки сервера через защищённую форму и хранится в файле .env.


## 11. Баланс ProxyAPI: проверка и монитор (новое)

Все функции с GPT — проверка работ, разбор сложных сокращений, аннотации источников — оплачиваются с баланса ProxyAPI. Сайт следит за балансом сам и заранее предупреждает преподавателя.

### 11.1. Как сайт узнаёт баланс

- ProxyAPI отдаёт текущий баланс по запросу `GET https://api.proxyapi.ru/proxyapi/balance` с ключом сайта ([ProxyAPI, баланс](https://www.proxyapi.ru/docs/balance)).
- По умолчанию ключу этот запрос недоступен. В личном кабинете ProxyAPI, в разделе «Ключи API», у ключа сайта нужно включить разрешение «Запрос баланса».
- Если у ключа задан бюджет, ProxyAPI возвращает остаток бюджета ключа, а не баланс аккаунта. Монитор показывает и остаток, и лимит бюджета.
- Сайт запрашивает баланс каждые 30 минут, после каждых 10 запросов к GPT и по кнопке «Проверить сейчас».
- Если средств не хватает, ProxyAPI отклоняет запрос с кодом 402 и ничего не списывает ([ProxyAPI, стоимость запроса](https://proxyapi.ru/docs/cost-of-request)). Сайт распознаёт этот ответ, даже если запрос баланса для ключа не включён.

### 11.2. Пороги

Преподаватель задаёт два порога в рублях в разделе «Настройки»:

| Уровень | Условие | Что делает сайт |
|---|---|---|
| Норма | Баланс выше порога «Мало» | Всё работает |
| Мало | Ниже порога «Мало» (по умолчанию 300 ₽) | Жёлтая плашка в админке, письмо преподавателю |
| Критично | Ниже порога «Критично» (по умолчанию 100 ₽) | Красная плашка, письмо. Новые проверки ещё отправляются |
| Нет средств | ProxyAPI ответил 402 или баланс ниже стоимости одной проверки | Отправка в GPT приостановлена, работы ждут в очереди, письмо |

- Письмо о каждом уровне отправляется один раз при переходе на этот уровень и повторяется не чаще раза в 12 часов, пока уровень держится.
- После пополнения сайт сам замечает рост баланса, снимает паузу, отправляет работы из очереди по порядку и присылает письмо «Баланс восстановлен, в очереди N работ».

### 11.3. Монитор в разделе «Настройки → ProxyAPI»

- Текущий баланс, время последней проверки, уровень: «норма», «мало», «критично» или «нет средств».
- Бюджет ключа: лимит и израсходовано, если бюджет задан.
- Расход: за сегодня, за 7 дней, за текущий месяц. Считается по уменьшению баланса между проверками. Пополнения в расход не входят.
- Средняя стоимость одной проверки работы — по последним 20 проверкам.
- Прогноз: «хватит примерно на N проверок» и «примерно до такой-то даты» при текущем темпе расхода.
- Очередь: сколько работ ждёт отправки, сколько из них из-за нехватки средств.
- Последние ошибки ProxyAPI: 401 (неверный ключ), 402 (нет средств), 429 (слишком много запросов) — с датой и пояснением.
- Состояние ключа: «запрос баланса разрешён / не разрешён». Если не разрешён — подсказка, где его включить.
- Кнопки: «Проверить сейчас», «Отправить пробный запрос», «Пополнить баланс». Последняя открывает раздел «Биллинг» личного кабинета ProxyAPI в новой вкладке. Пополнение выполняет сам преподаватель, сайт платежей не делает.
- Небольшой график баланса за 30 дней.

### 11.4. Где ещё видно

- На главной странице админки — плашка уровня «мало», «критично» или «нет средств» с прогнозом и кнопкой «Открыть монитор».
- В очереди проверок у работ, ждущих пополнения, — пометка «ждёт пополнения ProxyAPI».
- Студентам баланс не показывается.

### 11.5. Экономия средств

- В каждом запросе к GPT задаётся ограничение длины ответа (`max_completion_tokens`, по умолчанию 1500). Без него ProxyAPI при проверке достаточности средств закладывает максимально возможный ответ модели и может отклонить запрос даже при достаточном для обычной проверки балансе ([ProxyAPI, стоимость запроса](https://proxyapi.ru/docs/cost-of-request)).
- Рекомендуется задать бюджет ключа сайта в кабинете ProxyAPI, например на месяц курса. Это предохранитель от случайного перерасхода.
- Автопополнение в ProxyAPI сайт не включает и не настраивает: это решение преподавателя в его личном кабинете.
