# 07. Вход студентов: окно регистрации и личный ключ

Техническое задание для Claude Code. Редакция 1.2 от 25.11.2026. Дополняет пакет требований hwstud.ru редакции 2.1 и изменяет раздел 6 «Вход» в `docs/03-ARCHITECTURE.md`.

Изменения в редакции 1.2: личный ключ состоит из трёх русских слов (раздел 4.1).

Изменения в редакции 1.1 относительно 1.0:

- главное условие регистрации теперь окно регистрации на 10 минут, которое преподаватель открывает кнопкой в меню;
- код занятия (TOTP) и QR стали необязательным режимом, по умолчанию выключенным;
- лимиты попыток считаются по паре «IP + ник», общий лимит на IP поднят, чтобы не мешать аудитории за одним Wi-Fi.

## 0. Как работать с этим документом

1. Положи файл в `hwstud-claude/docs/07-AUTH-CLASS-CODE-KEYS.md`.
2. В `CLAUDE.md` добавь его в таблицу файлов. В порядок приоритета поставь сразу после `REQUIREMENTS.md`: по теме входа и регистрации этот документ важнее остальных.
3. Работай одним этапом, разбитым на шаги из раздела 12. После каждого шага запускай `pytest` и пиши короткий отчёт на русском языке. Следующий шаг начинай только после подтверждения.
4. Все правила `CLAUDE.md` о минимуме инструментов остаются в силе. Единственное исключение указано в разделе 10.

## 1. Цель и модель угроз

Сейчас студент входит только по нику, поэтому любой, кто знает чужой ник, может войти под ним. Новая схема должна:

- не давать войти под чужим ником, то есть защищать от подмены (impersonation);
- разрешать самостоятельную регистрацию только тогда, когда её открыл преподаватель, — обычно на занятии;
- обходиться без личных данных: ни почты, ни телефона, ни ФИО, ни внешних сервисов;
- дать преподавателю полное управление регистрацией, никами и ключами.

| Действие | Условие | Кто управляет |
|---|---|---|
| Регистрация нового ника студентом | Открыто окно регистрации для выбранной группы. В режиме кода занятия нужен ещё и действующий код или QR. | Преподаватель кнопкой «Регистрация» в меню |
| Создание ника преподавателем | Вход преподавателя, окно не нужно | Преподаватель |
| Вход под существующим ником | Личный ключ (personal key) этого ника | Сервер выдаёт ключ при регистрации или сбросе |

Остаточный риск режима без кода: пока окно открыто, зарегистрироваться может любой, кто знает адрес сайта. Его ограничивают короткое окно, лимит 20 ников в группе, живой список новых ников на экране преподавателя и быстрое удаление лишних (раздел 3.4).

Вне рамок задачи: почта, SMS, Telegram, приложения-аутентификаторы, двухфакторный вход преподавателя, защита от студента, добровольно отдавшего свой ключ другому.

## 2. Термины

| Термин | Значение |
|---|---|
| Окно регистрации, registration window | Интервал, в течение которого студенты выбранной группы могут сами создать ник. По умолчанию 10 минут. |
| Личный ключ, personal key | Три случайных русских слова вида `липа-ракета-гром`. Сервер хранит только хеш. |
| Карточка доступа, access card | Текст для пересылки студенту: адрес сайта, ник, ключ, короткая инструкция. Доступна 10 минут до подтверждения сохранения. |
| Код занятия, class code | Необязательный режим. 6 цифр по алгоритму TOTP (Time-based One-Time Password, одноразовый пароль на основе времени, RFC 6238). Виден только на экране преподавателя. |
| QR-токен, join token | Необязательный режим. Подписанная строка в ссылке из QR-кода. |

## 3. Окно регистрации

### 3.1. Хранение

- В таблице `groups` новый столбец `enroll_until` (время UTC в ISO 8601 или `NULL`).
- Группа открыта для самостоятельной регистрации, если `enroll_until` больше текущего времени сервера. Закрытие происходит само, простым сравнением времени: фоновых задач, cron и таймеров для этого не нужно.
- Столбец `enroll_open` больше не управляет самостоятельной регистрацией. Миграция переводит его в `0` у всех групп, а переключатель «Набор открыт» на странице групп заменяется окном регистрации. Сейчас `enroll_open` используется в `app/auth.py` (`find_student`, `create_student`), `app/routes/course_admin.py` (редактирование группы), `app/templates/admin_groups.html`, `tests/test_db_auth.py` и `tests/test_stage6.py`. Замени проверку `enroll_open` в `create_student` проверкой окна только для регистрации студентом. Создание ника преподавателем окно не проверяет. Если найдутся другие места, перечисли их в отчёте и согласуй с пользователем.
- Длительность окна хранится в `settings` (`registration_window_minutes`), по умолчанию `10`, допустимо от 5 до 15.

### 3.2. Кнопка в меню преподавателя

- В основном меню админки (`base.html`, навигация преподавателя) появляется пункт «Регистрация».
- Когда хотя бы одно окно открыто, у пункта видна метка с оставшимся временем, например «Регистрация · 07:42». Метка обновляется на любой странице админки тем же локальным скриптом, что и в разделе 3.3.
- Пункт ведёт на страницу `GET /admin/registration`.

### 3.3. Страница «Регистрация»

`GET /admin/registration`, доступна только преподавателю (`require_admin`).

Управление окном:

- список групп с флажками и количеством занятых мест, например «Группа 2 — 14 из 20»;
- кнопка «Открыть регистрацию на 10 минут» для отмеченных групп (число минут берётся из настройки);
- у каждой открытой группы — обратный отсчёт и кнопки «Продлить на 10 минут» и «Закрыть сейчас»;
- кнопка «Закрыть все».

Действия выполняются через POST-маршруты с CSRF-токеном:

- `POST /admin/registration/open` — `group_ids[]`;
- `POST /admin/registration/extend` — `group_id`;
- `POST /admin/registration/close` — `group_id` или `all`.

Продление отсчитывается от текущего времени окончания, а не от текущего момента. Суммарное окно не может быть длиннее 60 минут от момента открытия. Больше запросить нельзя, нужно закрыть окно и открыть заново.

Живой список новых ников:

- под управлением окна — таблица ников, зарегистрированных в текущих окнах: время, ник, группа;
- у каждой строки кнопка «Удалить» (раздел 3.4);
- обновление: локальный скрипт `static/js/registration.js` раз в 5 секунд запрашивает `GET /admin/registration/status`. Ответ — JSON: `{windows: [{group_id, group_name, seconds_left}], new_students: [{id, nick, group_name, created_at}]}`. Внешних скриптов нет, как требует `CLAUDE.md`.

Если включён режим кода занятия (раздел 7), на этой же странице есть кнопка «Показать код на экране». Она открывает полноэкранный вид с кодом и QR.

### 3.4. Быстрое удаление нового ника

- Для ника, созданного в текущем окне, у которого нет ни одной сданной работы и ни одного сообщения, удаление выполняется после простого подтверждения в браузере («Удалить ник ivanov_a?»), без отдельной страницы предупреждения.
- Для остальных ников используется существующий сценарий удаления с экраном предупреждения (`/admin/students/{id}/delete`).
- В обоих случаях работает `student_service.delete_student`. Ник и место в группе освобождаются.

### 3.5. Что видит студент

На шаге регистрации (раздел 6.1) студент видит только группы с открытым окном. Если открытых групп нет: «Регистрация сейчас закрыта. Её открывает преподаватель на занятии. Если вы пропустили занятие, напишите преподавателю — он создаст ник и пришлёт ключ».

Проверка окна выполняется на сервере при отправке формы. Если окно закрылось, пока студент заполнял форму: «Время регистрации истекло. Попросите преподавателя продлить регистрацию».

## 4. Личный ключ

### 4.1. Формат и хранение

- Ключ — три слова, выбранных случайно и независимо из словаря на 2048 слов, через дефис: `липа-ракета-гром`. Слова могут повторяться. Число вариантов — 2048³ ≈ 8,6·10⁹, около 33 бит случайности.
- Генерация: `secrets.choice` для каждого слова. Модуль `random` не использовать.
- Онлайн-подбор при таком размере невозможен из-за лимитов раздела 8: при блокировке ника после 5 неверных ключей на 15 минут остаётся не больше 480 попыток в сутки на ник. Риск остаётся только при утечке базы с хешами: scrypt делает перебор медленным, но не невозможным. Для учебного сайта этот компромисс принят ради удобства запоминания.

#### Словарь

- Файл `app/data/key_words_ru.txt`, UTF-8, одно слово в строке, ровно 2048 строк. Загружается один раз при старте приложения. Если в файле не 2048 уникальных слов, приложение не запускается и пишет понятную ошибку в журнал.
- Словарь составляет Claude Code по правилам ниже. Готовый файл показывается пользователю на проверку до перехода к шагу 2 (раздел 12). Пользователь может вычеркнуть слова, тогда их нужно заменить другими по тем же правилам.
- Правила отбора:
  - только имена существительные в именительном падеже единственного числа: `гром`, `липа`, `ракета`;
  - длина от 3 до 8 букв;
  - только строчные буквы `а–я` без `ё`, `ъ` и `й`. Буква `ё` исключена, потому что её часто пишут как `е`, а `ъ` и `й` — потому что их легко пропустить или спутать;
  - общеупотребительные, понятные студенту слова. Без имён собственных, аббревиатур, жаргона, устаревших и узкоспециальных слов;
  - без бранных, грубых, обидных, политических, религиозных и медицинских слов, без слов, связанных с насилием, а также без слов, которые в сочетании легко дают неловкий смысл;
  - без омографов с разным ударением (`замок`, `мука`) и без пар, различающихся одной буквой (`кот` и `код`, `роза` и `поза`), чтобы ключ можно было продиктовать без ошибок;
  - без однокоренных пар (`лес` и `лесник`).
- В тестах словарь проверяется автоматически: 2048 строк, все уникальны, все соответствуют `^[а-ик-щыьэюя]{3,8}$`, нет пар слов с расстоянием Левенштейна 1.

#### Ввод ключа

Сайт принимает ключ в свободной форме и перед проверкой нормализует его:

1. Приводит к нижнему регистру.
2. Если в строке есть латинские буквы, переводит их по раскладке ЙЦУКЕН: студент мог набрать ключ, забыв переключить раскладку (`kbgf` → `липа`). Перевод выполняется для всей строки по таблице клавиш, включая `[`, `]`, `;`, `'`, `,`, `.` и `` ` ``.
3. Заменяет `ё` на `е`, `й` на `и`. Этот шаг идёт после перевода раскладки, чтобы обработать и буквы, полученные из латиницы.
4. Разделителями считаются пробелы, дефисы, подчёркивания и `+`, повторы схлопываются. Запятая и точка разделителями не считаются: на раскладке ЙЦУКЕН это буквы `б` и `ю`.
5. После нормализации должно получиться ровно три слова. Каждое слово должно быть в словаре, иначе ключ неверный. Сообщение об ошибке — общее «Ник или ключ не подходят», без подсказки, какое слово не так.
6. Хеш считается от строки из трёх нормализованных слов через одиночный дефис.

Примеры, которые все равнозначны `липа-ракета-гром`: `Липа Ракета Гром`, `липа ракета гром`, `ЛИПА-РАКЕТА-ГРОМ`, `kbgf hfrtnf uhjv`, `липа  ракета-гром`.

#### Хранение

- Только хеш, через существующую `hash_password` (scrypt). Открытый ключ нигде не сохраняется: ни в базе, ни в логах, ни в `audit_log`, ни в сессии. Исключение — временный показ карточки в памяти процесса (раздел 4.3).

### 4.2. Связь с сессиями

- У каждой выдачи ключа (регистрация, сброс, смена) меняется `students.login_token`. Существующая проверка в `current_actor` тогда автоматически завершает все прежние сессии этого ника.
- Срок жизни cookie остаётся 90 дней (`SessionMiddleware`, `max_age`). Студент вводит ключ редко: на новом устройстве или после сброса.

### 4.3. Временный показ карточки доступа

Карточка показывается на отдельной странице после регистрации, создания ника преподавателем, сброса или смены ключа. Она доступна 10 минут и удаляется после нажатия «Я сохранил ключ». Это изменение согласовано с пользователем, чтобы случайное обновление страницы не приводило к потере ключа.

- Механизм: открытый ключ кладётся в память процесса под одноразовым случайным идентификатором со сроком 10 минут. Страница `GET /card/{id}` выводит карточку без удаления записи. `POST /card/{id}/saved` проверяет владельца и CSRF и удаляет запись. После перезапуска приложения карточка теряется, и это допустимо: преподаватель сделает сброс.
- Для студента карточка доступна только из его же сессии, для преподавателя — только из сессии преподавателя.
- Заголовки: `Cache-Control: no-store`, `Referrer-Policy: no-referrer`.
- Текст карточки, который копирует кнопка «Скопировать»:

```
Сайт курса: https://hwstud.ru/login
Ник: ivanov_a
Ключ: липа-ракета-гром

Ключ доступен в течение 10 минут. Сохраните его в заметках или менеджере паролей.
Ключ можно вводить с пробелами или дефисами, большими или маленькими буквами.
Если потеряете ключ, напишите преподавателю: он выдаст новый.
```

- На странице: предупреждение «Ключ больше не будет показан после истечения 10 минут или нажатия "Я сохранил ключ"», кнопки «Скопировать» и «Я сохранил ключ». Дополнительно — поле с текстом карточки на случай, если кнопка копирования недоступна.
- Ключ не передаётся в URL, в том числе в ссылке для пересылки: адрес попадает в историю браузера, журналы и превью мессенджеров.

## 5. Функции преподавателя для ников и ключей

Все функции находятся на странице «Группы» (`/admin/groups`) и в карточке ника. Каждая требует `require_admin`, CSRF-токен и пишет запись в `audit_log` (раздел 9).

### 5.1. Создать ник и получить ключ

- Форма: группа и ник. Ник проверяется теми же правилами `validate_nick` и на уникальность по `nick_norm`.
- Лимит группы (`max_members`, 20) соблюдается. Окно регистрации для этого не нужно.
- Результат: ник создан, ключ выдан, открывается карточка доступа (раздел 4.3), которую преподаватель пересылает студенту любым удобным способом.
- Желательно: массовое создание. Поле «по одному нику в строке» и группа. Результат — таблица карточек на одной странице, кнопка «Скопировать все» и выгрузка TXT, формируемая в памяти без сохранения на диск. Строки с ошибками (неверный формат, занятый ник, превышен лимит) пропускаются и перечисляются отдельно, остальные ники создаются.

### 5.2. Сбросить ключ

- Кнопка «Сбросить ключ» у ника. Подтверждение: «Старый ключ перестанет работать, студент выйдет на всех устройствах».
- Генерируется новый ключ, меняется `login_token`, обнуляется счётчик неудачных попыток и блокировка по нику (раздел 8), открывается карточка доступа.
- Работы, баллы и переписка ника не меняются.

### 5.3. Удалить ник вместе с ключом

- Используется существующий сценарий удаления (`/admin/students/{id}/delete`, `student_service.delete_student`) или быстрое удаление из раздела 3.4. Хеш ключа хранится в строке `students` и удаляется вместе с ней.
- После удаления ник и место в группе освобождаются, как сейчас.
- Проверь, что в базе не остаётся данных ключа, включая счётчики попыток.

### 5.4. Блокировка

Существующая функция блокировки сохраняется без изменений. Заблокированный ник не может войти даже с верным ключом.

### 5.5. Что видит преподаватель в списке ников

Колонки: ник, группа, дата создания, «Ключ выдан» (дата последней выдачи) или «Ключа нет», кто выдал (`студент`, `преподаватель`, `переходный режим`), дата последнего входа, статус блокировки, «Вход заблокирован до …», если сработал лимит по нику. Ключ преподаватель не видит никогда: посмотреть его нельзя, можно только сбросить.

## 6. Функции студента

### 6.1. Регистрация

Двухшаговая форма на `/login` в развитие текущей логики `login_submit`:

1. Студент вводит ник.
2. Если ника нет, показывается выбор группы — только группы с открытым окном (раздел 3.5). В режиме кода занятия добавляется поле «Код занятия»; если студент пришёл по QR, код не нужен.
3. При открытом окне (и верном коде, если режим включён) ник создаётся, выдаётся ключ, открывается карточка доступа, и студент сразу входит.

### 6.2. Вход

1. Студент вводит ник.
2. Если ник существует — поле «Личный ключ».
3. Если ключ верный и ник не заблокирован — вход.
4. Сообщения об ошибке:
   - «Ник или ключ не подходят» — при неверном ключе;
   - «Доступ для этого ника заблокирован преподавателем» — для заблокированного;
   - «Для этого ника ещё не выдан ключ. Обратитесь к преподавателю» — для ника без ключа.

Сайт и сейчас сообщает, что ник занят, поэтому дополнительного скрытия существования ника не требуется.

### 6.3. Смена ключа в кабинете

Кнопка «Получить новый ключ» в кабинете студента. Требует ввести текущий ключ. Результат: новый ключ, смена `login_token` (выход на других устройствах), карточка доступа, запись в `audit_log`.

### 6.4. Переходный режим для существующих ников

Ники, созданные до этой доработки, ключа не имеют.

- Если такой студент уже вошёл и его сессия действительна, в кабинете появляется баннер «Получите личный ключ — без него вы не сможете войти с другого устройства» с кнопкой. Ключ выдаётся без ввода старого ключа: его нет. Источник выдачи — `переходный режим`.
- Вход по одному нику без ключа после миграции невозможен (раздел 6.2).
- В админке есть кнопка «Выдать ключи всем никам без ключа». Результат — таблица карточек, как при массовом создании (раздел 5.1).

## 7. Необязательный режим: код занятия и QR

По умолчанию выключен (`settings.class_code_required = 0`). Включается переключателем на странице «Регистрация». Когда режим включён, студенту для регистрации нужны и открытое окно, и действующий код. Окно остаётся обязательным в любом режиме.

### 7.1. Код

- Алгоритм RFC 6238: HMAC-SHA1, 6 цифр. Реализуй его в `app/services/class_code.py` только на стандартной библиотеке (`hmac`, `hashlib`, `struct`, `time`). Библиотеки `pyotp` и аналоги не используй.
- Код и вычисляет, и проверяет один и тот же сервер, поэтому часы телефона на результат не влияют.
- Секрет: 20 случайных байт в `settings.class_code_secret`, в base32. Создаётся при первом обращении. В логи, ответы и выгрузки не попадает.
- Период: `settings.class_code_period`, 60–300 с, по умолчанию 120.
- Принимаются коды текущего и предыдущего периодов. Сравнение — через `hmac.compare_digest`.

### 7.2. Экран для проектора

- `GET /admin/registration/code` — полноэкранный вид: 6 цифр в виде `123 456`, обратный отсчёт периода, QR, названия открытых групп. Обновление раз в 5 секунд через `GET /admin/registration/code/current`.
- Код и QR показываются только преподавателю и только пока открыто хотя бы одно окно. Когда окна нет, экран показывает «Регистрация закрыта».
- QR содержит `https://hwstud.ru/join?t=<QR-токен>`. Код рисуется на сервере в SVG прямо в HTML (раздел 10).
- Заголовки: `Cache-Control: no-store`, `Referrer-Policy: no-referrer`.
- Кнопка «Сменить секрет» делает недействительными прежние коды и QR-токены.

### 7.3. QR-токен

- `itsdangerous.URLSafeTimedSerializer` (библиотека уже установлена) с ключом из `SESSION_SECRET`, солью `join-v1` и первыми 8 символами хеша секрета кода. Внутри — `{"p": номер_периода}`.
- Токен действителен, если подпись верна, `p` равен текущему или предыдущему периоду и окно открыто хотя бы для одной группы.
- `GET /join?t=…` при верном токене открывает форму регистрации без поля кода. Токен передаётся в форму скрытым полем и проверяется повторно при отправке. При неверном токене открывается страница «Ссылка устарела. Отсканируйте QR-код на экране ещё раз».

## 8. Ограничения попыток

### 8.1. Почему по паре «IP + ник»

Аудитория за одним Wi-Fi выходит в интернет с одного внешнего IP. Текущее ограничение `login_submit` — 20 попыток в час с одного IP (`student:{ip}`, 20, 3600). Его исчерпают 20 студентов, регистрирующихся одновременно. Поэтому основные лимиты считаются по паре «IP + нормализованный ник». Лимит на один IP остаётся только как верхний потолок против массового перебора.

### 8.2. Таблица лимитов

| Ключ счётчика | Что считается | Лимит | Окно | Ответ при превышении |
|---|---|---|---|---|
| `login:{ip}:{nick_norm}` | Любые отправки формы входа или регистрации для этого ника с этого IP | 10 | 10 мин | 429, «Слишком много попыток для этого ника. Повторите через 10 минут» |
| `login_ip:{ip}` | Все отправки формы входа и регистрации с этого IP, по всем никам | 300 | 1 ч | 429, «Слишком много попыток с вашей сети. Повторите позже» |
| `register_ip:{ip}` | Успешные регистрации новых ников с этого IP | 60 | 1 ч | 429, «Слишком много регистраций с вашей сети. Обратитесь к преподавателю» |
| `class_code:{ip}:{nick_norm}` | Неверный код занятия (режим из раздела 7) | 5 | 10 мин | 429, «Слишком много неверных кодов. Повторите через 10 минут» |
| `class_code_ip:{ip}` | Неверные коды занятия с IP по всем никам | 100 | 10 мин | 429, как выше |
| `nick_format:{ip}` | Отправки с ником неверного формата (ник не нормализован, поэтому считается только по IP) | 50 | 10 мин | 429, «Слишком много попыток. Повторите позже» |
| Блокировка по нику (хранится в базе) | Неверные ключи подряд для ника, с любых IP | 5 | Блокировка 15 мин | 423, «Слишком много неверных попыток для этого ника. Повторите через 15 минут» |

Пояснения:

- Значения лимитов вынеси в константы в одном месте (`app/config.py` или раздел лимитов в `03-ARCHITECTURE.md`, раздел 13), а не разбрасывай по коду.
- Существующий вызов `limiter.allowed(f"student:{ip}", 20, 3600)` в `login_submit` заменяется лимитами из таблицы.
- Счётчики по IP и по паре хранятся в памяти (`RateLimiter`) и сбрасываются при перезапуске — это допустимо. Блокировка по нику хранится в `students.key_failed_count` и `students.key_locked_until` и переживает перезапуск.
- Блокировку по нику может намеренно вызвать посторонний, вводя неверные ключи для чужого ника. Это осознанный компромисс: последствие — 15 минут ожидания, и преподаватель снимает блокировку сбросом ключа (раздел 5.2).
- Верный ключ обнуляет счётчик неверных попыток ника и счётчик `login:{ip}:{nick_norm}`.
- Лимиты попыток не действуют на преподавателя, создающего ники в админке. Вход преподавателя сохраняет свои текущие ограничения.

### 8.3. Определение IP за Caddy

Приложение слушает 127.0.0.1:8000 за Caddy. Сейчас `client_ip` возвращает `request.client.host`, а служба `deploy/hwstud.service` запускает uvicorn с `--proxy-headers`. В этом случае uvicorn подставляет адрес клиента из `X-Forwarded-For`, но только для запросов от доверенного прокси: по умолчанию `--forwarded-allow-ips` равен 127.0.0.1. Caddy по умолчанию не доверяет входящему `X-Forwarded-For` от клиента и записывает в заголовок настоящий адрес.

Ничего не переписывай, но проверь и закрепи тестами:

- `--forwarded-allow-ips` не расширен до `*` ни в unit-файле, ни в коде;
- в `deploy/Caddyfile` нет `trusted_proxies`, которые позволили бы клиенту подставить свой `X-Forwarded-For`;
- тест: запрос с поддельным `X-Forwarded-For` не от 127.0.0.1 не меняет IP, по которому считаются лимиты.

Если что-то из этого не так, остановись и сообщи пользователю. Без этого лимиты по IP можно обойти подменой заголовка.

## 13. Тесты (`tests/test_registration_keys.py` и дополнения к существующим)

Окно регистрации:

- без открытого окна студент не может зарегистрироваться ни в одну группу, форма показывает сообщение из раздела 3.5;
- открытое окно пускает регистрацию только в отмеченные группы;
- через 10 минут (время подменяется в тесте) регистрация отклоняется без каких-либо фоновых задач;
- продление добавляет 10 минут к текущему окончанию, а суммарное окно не превышает 60 минут;
- «Закрыть сейчас» и «Закрыть все» срабатывают сразу;
- окно закрылось между открытием формы и отправкой: регистрация отклоняется с сообщением об истечении времени;
- лимит 20 ников в группе соблюдается и при открытом окне;
- `GET /admin/registration/status` возвращает открытые окна и ники текущих окон, без входа преподавателя недоступен;
- быстрое удаление работает только для ника без работ и сообщений, остальные отправляются на страницу предупреждения.

Лимиты:

- 25 студентов с одного IP и разными никами регистрируются и входят без отказа;
- 11-я попытка для одного ника с одного IP за 10 минут получает 429, другой ник с того же IP при этом проходит;
- 301-я отправка с одного IP за час получает 429;
- 5 неверных ключей подряд блокируют ник на 15 минут с любых IP, блокировка сохраняется после перезапуска, сброс ключа её снимает;
- верный ключ обнуляет счётчики ника;
- подделанный `X-Forwarded-For` от клиента не меняет IP, по которому считаются лимиты.

Ключи и карточки:

- ключ состоит из трёх слов словаря, слова выбираются через `secrets`;
- ключ нормализуется: все примеры из раздела 4.1 дают один и тот же хеш, включая ввод в латинской раскладке и с `ё`;
- ввод из двух или четырёх слов, а также со словом не из словаря отклоняется с общим сообщением;
- словарь: 2048 уникальных слов, формат по регулярному выражению из раздела 4.1, нет пар на расстоянии Левенштейна 1; при испорченном файле словаря приложение не запускается;
- в базе хранится только хеш, поиск открытого ключа по всем таблицам и `audit_log` ничего не находит;
- карточка доступна 10 минут до подтверждения сохранения, после подтверждения или истечения запрос возвращает 404, чужая сессия её не получает;
- вход по верному ключу работает, по неверному — нет, ник без ключа не входит;
- сброс ключа отзывает действующую сессию: следующий запрос со старой cookie ведёт на `/login`;
- удаление ника освобождает ник и место в группе и не оставляет данных ключа;
- создание ника преподавателем работает без открытого окна и соблюдает лимит 20;
- массовое создание: верные ники созданы, ошибочные перечислены, лимит группы соблюдён.

Режим кода занятия (шаг 5):

- TOTP совпадает с тестовыми векторами RFC 6238 для SHA1, если обрезать их до 6 цифр;
- код текущего и предыдущего периодов принимается, другие — нет;
- при включённом режиме регистрация без кода отклоняется даже при открытом окне;
- при закрытом окне регистрация отклоняется даже с верным кодом или токеном;
- смена секрета делает недействительными прежние коды и токены.

Общее:

- все POST-маршруты требуют CSRF, маршруты `/admin/registration*` без входа преподавателя перенаправляют на вход;
- существующие тесты `test_web_auth.py`, `test_db_auth.py` и `test_delete_student.py` обновлены под новую схему и проходят.

## 14. Критерии приёмки

1. В меню преподавателя есть пункт «Регистрация». Одна кнопка открывает регистрацию для выбранных групп на 10 минут, в меню виден обратный отсчёт.
2. Через 10 минут регистрация закрывается сама. Продление и досрочное закрытие работают.
3. Пока окно открыто, преподаватель видит новые ники в течение 5 секунд после регистрации и может удалить лишний ник в один клик с подтверждением.
4. 20 студентов из одной аудитории за общим Wi-Fi регистрируются за время окна без отказов из-за лимитов.
5. Без открытого окна студент зарегистрироваться не может. Преподаватель при этом может создать ник и выдать ключ в любой момент.
6. Войти под существующим ником без его ключа нельзя.
7. Преподаватель создаёт ник, копирует карточку и пересылает её. Студент входит по карточке.
8. Преподаватель сбрасывает ключ: старый ключ и все сессии перестают работать, по новому ключу вход проходит.
9. Преподаватель удаляет ник: ник свободен, ключа в базе нет.
10. Открытые личные ключи, коды и токены не встречаются в базе, логах, `audit_log`, CSV и резервных выгрузках; личные ключи хранятся только как хеши. Согласованное исключение — `class_code_secret` в защищённой SQLite и её резервных копиях, поскольку секрет нужен серверу для вычисления TOTP.
11. Новых внешних сервисов и исходящих запросов не появилось. Новая зависимость, только если выполнен шаг 5, — `segno`.
12. Все тесты `pytest` проходят. В `FINAL-REPORTS.md` добавлен отчёт по этапу.
